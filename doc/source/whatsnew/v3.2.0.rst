Other enhancements
^^^^^^^^^^^^^^^^^^
- Display formatting for complex numbers in ``object`` dtype and for ``interval`` dtype values with float endpoints now respects the ``display.precision`` and ``display.float_format`` options (:issue:`25920`).
- The :class:`ExtensionArray` base tests in ``pandas.tests.extension.base`` now issue a :class:`errors.PerformanceWarning` when the array uses the default, possibly slow, implementation of ``unique``, ``factorize``, ``argsort``, ``argmin``, ``argmax``, or ``searchsorted`` (:issue:`24433`)

.. _whatsnew_320.api_breaking.deps:

Increased minimum versions for dependencies
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
Some minimum supported versions of dependencies were updated.
If installed, we now require:

+-----------------+-----------------+----------+---------+
| Package         | Minimum Version | Required | Changed |
+=================+=================+==========+=========+
|                 |                 |    X     |    X    |
+-----------------+-----------------+----------+---------+

For `optional libraries <https://pandas.pydata.org/docs/getting_started/install.html>`_ the general recommendation is to use the latest version.
The following table lists the lowest version per library that is currently being tested throughout the development of pandas.
Optional libraries below the lowest tested version may still work, but are not considered supported.

+-----------------+-----------------+---------+
| Package         | Minimum Version | Changed |
+=================+=================+=========+
|                 |                 |    X    |
+-----------------+-----------------+---------+

See :ref:`install.dependencies` and :ref:`install.optional_dependencies` for more.

.. _whatsnew_320.api_breaking.other:

Other API changes
^^^^^^^^^^^^^^^^^
- :class:`DataFrame`, :class:`Index`, :class:`Series` and :func:`array` now convert numeric data with non-native byte order (e.g. ``">f4"`` on a little-endian machine) to native byte order, including through :meth:`DataFrame.astype`, :meth:`Index.astype` and :meth:`Series.astype`. Previously the byte order was kept, and many operations, such as :meth:`Index.get_indexer`, :meth:`Series.unique` and groupby and window aggregations, raised ``ValueError: Big-endian buffer not supported on little-endian compiler`` (:issue:`53234`)

Performance improvements
~~~~~~~~~~~~~~~~~~~~~~~~
